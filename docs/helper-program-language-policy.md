# 補助プログラムの言語の選び方

設定だけでは書けない処理のために、
このリポジトリは`pkgs`などに自作の補助プログラムを持っています。
新しく書く時の言語は、
以下を上から順に当てはめて最初に合ったものにします。

- 問題を明らかに手っ取り早く解決できる優れたライブラリがあり、それをスムーズに使えるなら、その言語
- 非常に単純な処理ならシェルスクリプト
- レイテンシが重要ならRust
- 特に理由が無ければHaskell

これは原則なので例外はあります。
基準と違う言語を選ぶ時は、
その理由をパッケージの`package.nix`の冒頭のコメントに書いてください。

## ライブラリを理由に選ぶ場合

ライブラリを理由に言語を選ぶのは、
そのライブラリが無いと自前で大きな実装を抱えることになる場合です。
ComfyUIのカスタムノードがPythonなのは、
ComfyUI自身がPythonのモジュールとしてノードを読み込むためです。
どの言語にもある程度のライブラリで済むなら、
この基準には当てはまりません。

## シェルスクリプト

シェルスクリプトにするのは、
外部コマンドを順に呼ぶだけのような非常に単純な処理です。
以下のどれかに当てはまるなら、
単純とは言えないので他の言語にします。

- 分岐や状態の持ち回りが増えて、読んで追うのが難しい
- 信頼できない入力を解釈する
- 構造のあるデータを組み立てたり読んだりするのが処理の中心になる
- 振る舞いをテストで固定したい

## Rust

Rustにするのは、
人の操作のたびに起動されるコマンドのように、
起動や応答の遅さがそのまま体感に出るものです。
常駐して数分おきに動くものや、
ビルドやサービスの起動時に一度だけ走るものは、
レイテンシが重要とは言えません。

## Haskell

`pkgs`にパッケージとして置く時は、
`pkgs/git-repo-subscribe`などの既存のパッケージと同じ構成に揃えます。
himariを使うcabalプロジェクトにして、
テストはsandwichで書きます。
外部コマンドの出力のような複雑な文字列のパースには、
手書きの分割や再帰ではなくmegaparsecを使います。

この構成はパッケージとして置く時の決まりです。
モジュールの中にインラインで書いて済む小さなものまで、
cabalプロジェクトにする必要はありません。
`pkgs.writers.writeHaskellBin`などでそのまま書いて構いません。
