# インターネットプロトコルのバージョンへの対応方針

IPv4とIPv6のどちらをどう使うかの方針です。

## 前提

IPv6が今のインターネットプロトコルで、
IPv4は過去との互換性のために残っているものだと考えています。
IPv4にはいずれ無くなってほしいと思っています。

一方で、
インターネットにはIPv4でしか届かない相手がまだ多く残っています。
IPv4を前提に作られたソフトウェアや、
IPv4にしか無いプロトコルもあります。
それらを使えなくしてまでIPv4を無くすことは望んでいません。

## 基本方針

自分で構成するものは全てIPv6で動くようにします。
IPv6に対応していないことは許容しません。

### 指定する時はIPv6

通信先や待ち受け先のアドレスを自分で指定する時は、
IPv6のアドレスを使います。
アドレスファミリを決める必要が無い所では、
名前で指定したりワイルドカードで待ち受けたりして、
どちらとも決めない書き方を選びます。

テストのデータや説明の中のアドレスも同じです。
IPv4である必要が無ければ、
IPv6かアドレスファミリを決めない書き方にします。

### IPv4はレガシー対応に限る

IPv4を持たせたり使ったりするのは、
IPv4でしか届かない相手や、
IPv4を前提にした相手と繋がる必要がある時だけです。
その場合もIPv4だけにはせず、
IPv6と並べて両方で動かします。

IPv4とIPv6のどちらを先に使うかを選べる時は、
IPv6を先にしてIPv4は予備にします。

外から引かれる名前にIPv6のアドレスがあっても、
IPv4のアドレスは互換性のために残します。
IPv6で届かない利用者を締め出す理由はありません。

### 既定のIPv4はわざわざ消さない

ソフトウェアやOSが既定で付けたり使ったりするIPv4を、
わざわざ無効化する設定は書きません。
IPv6に対応していないことは許容しませんが、
IPv4が残っていることまで消して回ろうとは思いません。

IPv4を無くすためだけに、
大きな副作用を受け入れたり、
文書化されていない機能に頼ったりもしません。

## 判断の記録

IPv4を持たせたり使ったりしている所には、
何のためにIPv4が要るのか、
どの相手がIPv4でしか届かないのかを、
設定の近くのコメントに書きます。
相手がIPv6に対応した時に、
外せるかどうかを見直せるようにするためです。

既定のまま付いてくるIPv4は、
何もしていないので記録しません。
