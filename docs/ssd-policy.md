# SSDの使い方の方針

SSDの性能と寿命を保つための全体方針です。

## 前提

SSDは書き込みの前に消去が必要で、
消去はページより大きなブロック単位でしか行えません。
そのため空き領域が少ないと、
ガベージコレクションでまだ有効なデータを移し替える量が増え、
書き込み増幅が大きくなります。
書き込み増幅はそのまま書き込み性能の低下と寿命の消費になります。
SLCキャッシュも空き領域から作られるので、
埋まるほど縮んで書き込みが遅くなります。

ファイルシステムの空きは、
TRIMでSSDに伝わって初めてSSDにとっての空きになります。
TRIMが届いている空き領域は、
メーカーが確保している予備領域と同じように働きます。

## 空き容量

SSDの上のファイルシステムは、
容量の10%以上を必ず空けておきます。
これを下回る状態は異常として扱い、すぐに解消します。

普段は15%以上空いている状態を保つようにします。
性能が落ち始める前に余裕を持たせるためです。

10%はメーカーがover-provisioningとして勧めている値に合わせています。
例えばSamsung Magicianのover-provisioning機能は既定で容量の10%を割り当てます。

### 自動で増えるものは自動で減らす

スナップショットやビルドの成果物のように、
人が見ていなくても自動で容量を増やしていくものには、
空き容量が減った時に自動で削除して空きを取り戻す仕組みを必ず組にします。
人が気付いて手で消すことを前提にはしません。

### btrfsは未割り当て領域で見る

btrfsはdataやmetadataのチャンクを確保してから中にデータを置きます。
`df`の空きが十分でも、
新しいチャンクを確保するための未割り当て領域が尽きると、
metadataが確保できずに書き込めなくなります。
未割り当て領域が無いと、
回収のためのbalanceすら実行できなくなります。

btrfsの空き容量は`btrfs filesystem usage`のDevice unallocatedで見ます。
上の割合とは別に、
デバイスごとに数GiB以上の未割り当て領域を残します。
dataとmetadataのチャンクはデバイスあたり最大1GiB程度なので、
それを何度か確保できる量です。
50GiB以下の小さなファイルシステムでは、
metadataのチャンクは256MiBになります。

未割り当て領域が減った時は、
`-dusage`や`-musage`で使用率の低いチャンクに絞ったbalanceで回収します。
フィルタ無しのbalanceは全データを書き直すので行いません。

## TRIM

空き領域を予備領域として働かせるため、
TRIMが止まらないようにします。

TRIMの送り方には以下の3つがあります。

- 定期的にまとめて送る(`fstrim`)
- 削除した領域をファイルシステムが溜めておき、後でまとめて送る(btrfsの`discard=async`)
- 削除のたびにその場で送る(`discard`や`discard=sync`)

前の2つを使います。
最後の方式は削除の度にI/Oが詰まって性能が落ちるので使いません。
前の2つは併用しても問題ありません。

## 健全性の監視

### 交換の判断

NVMeのSMART/Health Informationで、
以下のどれかに当てはまったら交換を準備します。

- Critical Warningのビットが立っている
- Available SpareがAvailable Spare Thresholdを下回っている
- Media and Data Integrity Errorsが増えている
- Percentage Usedが95%を超えている

TBWは保証の上限であって故障の予測ではありません。
TBWに近づいたこと自体は交換の理由にせず、
上の実測値で判断します。

### 温度

温度はComposite Temperatureで見ます。
許容範囲は機種ごとに違うので、
一般的な数値ではなく、
`nvme id-ctrl`の`wctemp`(警告)と`cctemp`(危険)をそのドライブの基準にします。
普段の負荷で`wctemp`に近づくなら、
ヒートシンクやエアフローを見直します。

### データの破損の検出

btrfsはチェックサムを持っていますが、
照合するのは読んだ時だけです。
滅多に読まないデータの破損にも気付けるように、
定期的にscrubで全体を読みます。

## 書き込み量の削減

今のSSDは普通の使い方では寿命を使い切る前に買い替えになることが多いです。
書き込みを減らすためだけに、
使い勝手やデータの安全性を犠牲にすることはしません。

`noatime`のように副作用がほとんど無く書き込みを減らせるものは使います。

## キャッシュ専用のSSD

bcacheのキャッシュデバイスのように、
SSDを丸ごと他の記憶装置のキャッシュとして使う場合は、
空き容量の方針は当てはまりません。
空き領域の管理はキャッシュの仕組みに任せます。
健全性の監視の方針はそのまま当てはまります。

## 判断の記録

ここに書いた方針を満たすための個別の設定は、
その設定の近くのコメントに理由を書きます。
方針から外れる設定をする時も、
なぜ外れるのかを設定の近くのコメントに残します。
