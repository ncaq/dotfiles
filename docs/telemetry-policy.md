# テレメトリへの対応方針

ソフトウェアが利用状況を開発元へ送る、
いわゆるテレメトリにどう向き合うかの方針です。

## 前提

知識は自由であるべきです。
自分が使っているソフトウェアがどう使われ、
どこで失敗しているかは、
開発元が次に何を直すべきかを決めるための知識です。
それを手元に留めておく理由は、
機密性を守る必要がある時にしかありません。

このリポジトリが管理しているのは個人のデスクトップ、ラップトップ、自宅サーバです。
商業には使っておらず、
守るべき秘密は限られています。

## 基本方針

センシティブではない情報はテレメトリに渡して、
開発に貢献します。

といっても積極的に有効化して回るわけではありません。
既定で送る作りになっているものを、
わざわざ無効化しないという程度の話です。
既定で無効なものを有効にするための設定を書いたり、
初回の同意を求める対話に応じて回ったりはしません。

無効にするのは、
以下のようにセンシティブな情報が含まれる場合に限ります。

- ファイルの中身、プロンプトの文面、メールの本文のような、自分が書いたり扱ったりしているデータそのもの
- 認証情報、鍵、トークン
- 自宅のネットワーク構成やIPアドレスのような、侵入の足場になる情報
- 他人の個人情報

どのコマンドをどの順番で使ったか、
どの機能がどれだけ失敗したか、
どのバージョンをどのOSで動かしているか、
といった利用状況や環境の統計はセンシティブではありません。

## 判断の記録

既定のまま送らせているものは、
何もしていないので記録しません。

送られる内容を見てセンシティブだと判断して無効にしたものは、
その設定の近くのコメントに理由を書きます。
後から送る内容が変わった時に、
判断を見直せるようにするためです。
