# PRに勝手にpushしない

PRに勝手に`git push`することは基本的に控えてください。

何故ならば、
大抵のリポジトリにはCIが用意されており、
自動コードレビューも行われるからです。

PRに勝手にpushされると、
長大な時間のかかる自動コードレビューが中途半端に走ってしまいます。
コードレビュー用のAPIも無駄に使用されることに繋がります。

コードレビューに対応する時にはコミットは後で見やすいように個別に行いたいですが、
pushはある程度まとまってから行いたいです。
なのでコミットのたびに勝手にpushすることは控えてください。

## pushの前のローカルコミットに言及しても問題ない

コードレビューに対する返信やresolveはpushの前に行っても構いません。
返信コメントにまだ404となってしまうコミットハッシュへのリンクを貼り付けるのも特に問題ありません。

## PRに勝手にpushしても構わない場合

バッチ的に多数のリポジトリや多数のPRを処理することが求められている時や、
スキルやプロンプトの中で明示的にpushをすることが指示されている場合は、
自動化のためにPRにpushを勝手に行っても構いません。

## PRが無い作業用のブランチへのpushは基本的に許容されています

リモートの環境にデプロイすることが必要な時などに、
PRを作らずに作業用のブランチをpushすることは許容されます。
PRが無ければ自動コードレビューは走らないからです。

デフォルトブランチへ直接pushすることは別の話です。
明示的に指示された場合にのみ行ってください。
